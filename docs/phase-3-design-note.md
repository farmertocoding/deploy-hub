## 1. What lands this phase

Phase 2.5 left a live substrate: T1/T2/T3 all green on this host (16 T3 passed), CheckRun + drills + reaper, `HUB_TEST_MODE`, `assert_test_zone`, a working `DnsProvider` seam with a real Cloudflare client for **one test zone**. Phase 3 turns that into the operator-facing half of the product.

1. **Product Cloudflare DNS adapter.** `providers/cloudflare.py` implements the pinned `DnsProvider` (§D5) against a **`DnsZone`** row — the single zone identity (name, provider, vault token ref, purpose, proxied default). `providers/registry.py::dns_provider_for(zone)` is the only construction path. D-028's test-plane client stops being a second Cloudflare implementation: the product adapter is what the credentialed T3 leg drives, under `HUB_TEST_MODE`, against the allowlisted test zone (D-034). Prod tokens are vault-held, per-zone scoped, and **never** reach a target (SEC-B2).
2. **SEC-B5 token discipline, mechanised.** Two token refs per account (`dns`, `edge`); the adapter loads only `dns`. A daily Beat audit calls `/user/tokens/verify`, compares the returned scopes to the declared minimum for that zone, and files a Finding (P2) on excess or on a Global-API-Key shape. The `edge` token is modelled and audited now; the §6.5 L5 attack playbook that uses it stays Phase 4.
3. **Origin certificates + `TlsCertificate` (§B2).** Proxied sites: the Hub generates the keypair, issues a Cloudflare **Origin CA** certificate, stores the key in the vault, pushes cert+key `0400` through Transport, points Caddy at them (`automatic_https.disable` already set), SSL mode Full (strict). Unproxied public sites: Hub-central DNS-01 is **not built this phase** and the pipeline **refuses by name** rather than enabling Caddy DNS-01 — the refusal is SEC-B2's proof, because the alternative is a zone-scoped token on every target. Expiry watch on the V9 thresholds (uploaded 45/21/7 = P3/P2/P1; auto-renewed 7/1 = P2/P1).
4. **Findings model (§F2) as the one attention queue.** `Finding(source_engine, severity, entity, title, body, fix_action, state, first_seen, last_seen, fingerprint)`; accept-risk requires a one-line reason and re-surfaces on fingerprint change. Every alert is a Finding with the same fingerprint (§7 of alert-protocol); the pager is only the interrupt.
5. **Alert protocol, hard-coded.** One rules table transcribed from alert-protocol §2 in `monitor/alert_rules.py`; `classify(kind)` **raises** on an unregistered alert kind — an unclassified alert type structurally cannot ship (ALERT-P1-ROWS). Anti-noise engine (§4): open after 3 failures / close after 2, flap collapse (≥3 cycles/30 min → one P2 FLAPPING), root-cause suppression (host-down suppresses its sites, zone-down its hosts, with the suppressed list inside the one alert), ack ≠ resolve, storm breaker (>10 pushes/10 min → one P1 + 10-min summaries), and the recovery notice that alert-protocol §3 makes mandatory.
6. **ntfy pager as a provider seam.** `Pager` in `providers/base.py`, `providers/ntfy.py`, `FakePager` in `providers/fakes.py` and the default everywhere in tests. Per-server publish tokens and topic names are vault secrets (M3); push bodies are minimized (object · severity · duration · deep link, host aliases never raw IPs) and pass the scrubber; break-glass text lives only in the **email** copy and is labelled advisory-only. When a target's Hub-side probing goes live the provisioner removes that host's `server-watch.sh` cron (review3 §Q8: no double execution, no double paging).
7. **Watcher-of-the-watcher (§5).** Dead-man ping fires at the **end of a completed probe cycle** (scheduler + broker + worker + SSH proven, not "Beat ticked"); the canary rule precedes any mass-outage declaration and degrades to one "Hub egress degraded" P2. `UptimeEvent` rows carry the probe transitions the hysteresis engine reads; ws-class sites' primary metric is last-tick age + connection count (§O3), not request lines.
8. **Log backpressure + traffic ingest (§C4).** Caddy's native roller (`roll_size 100MiB`, `roll_keep 5`) becomes a versioned catalog entry (D8 bump, logrotate stays as the backstop); the per-pull byte cap gains the degrade path — over the cap the on-host one-liner returns counts by status/IP and the Hub ingests a summary flagged `sampled: true`. Minute `TrafficStat` rows land; hour/day rollups and the retention janitor are the cut line.
9. **Operator UX (§F1/§F2/§F4/§F5/§F8).** Object-centric nav (Home = map + fleet cards, Sites, Targets, Deploys, Findings, Settings); the advisors are tabs, not pages. Degraded 10 s REST polling with a visible pill when WS is down (RT-35). Action tiers as one declarative table: T2 confirm shows the diff, T3 (rollback/restart/re-run) is one click + undo toast and can never be gated by step-up. The T1 **hardware**-touch half is Phase 4 (D-040). Every new state is in the simulation seed — that is what retires the UX-F8 waiver.
10. **Map v1 (§9.6.1).** Zones → hosts → containers + Hub + Cloudflare edge from one `map.graph` snapshot/topic; solid public vs dashed mesh paths; status never colour-only; list-view toggle. Plain SVG — the §J3 library question stays open until a 30-node prototype demands it (D-041).
11. **Adopt-existing-site, compose-aware (§E6 + J7 finding 3).** `provision/adopt.py` parses `docker-compose*.yml` **without executing anything** (M1) and classifies services into web / worker / beat-scheduler / one-shot migrate / db / cache / site-owned edge, emits an adoption plan as Findings plus one V5-shaped manifest proposal, and refuses to flip DNS before the temp-subdomain deploy verifies. Site-owned Caddy vs host Caddy is surfaced as an operator decision, never auto-taken; registered volumes (N6) block or migrate.
12. **Phase 2.5 parked findings retired here:** I5 + M2 (the hub-down drill never had a prober; nothing wrote `due_at`, so `find_missed` was inert in prod) · M1 (restore stub wrote SUCCEEDED) · M4 (LE waiver not self-refusing) · I1 (self-declared `t3` marks were ungated) · the dual `HUB_TEST_ZONE_SLUGS` zone namespace · one-way custody parity · the scrubber's single-class token slice (the pager reuses the scrubber, so this becomes load-bearing) · the `_ws_frame` extended-length read loops (`deploys/steps.py:482/487`). **I2** (worker_entry reaching into `tests/`) and **I4** (duplicated Multipass driver) are scheduled on the may-slip line.

## 2. Interfaces / tables that change

**New models (all §4-named, none invented):** `DnsZone(name, provider, token_ref, purpose, proxied_default)` · `TlsCertificate(site, mode ∈ {origin_cert, uploaded, auto, hub_dns01}, not_after, fingerprint, key_ref, pushed_at)` · `Finding` (§F2 verbatim, `fingerprint` unique, `accepted_reason`) · `AlertState(fingerprint 1:1, consecutive_fail, consecutive_ok, opened_at, closed_at, last_push_at, acked_at, transitions JSON)` · `AlertDelivery(finding, channel ∈ {ntfy, email}, severity, sent_at, ok, detail)` · `UptimeEvent(entity, kind, state, at)` · `TrafficStat(site, bucket_start, granularity, requests, bytes, status_counts JSON, sampled bool)`. `DnsRecord` gains `zone` FK + `observed_value` / `last_verified` (§D3). `CheckRun.Kind` gains `pager`, `cf_token_scope`, `cert_expiry`.

**Interfaces:** `providers/base.py` gains `Pager.publish(severity, title, body, *, tags)` and `OriginCertIssuer.issue(zone, hostnames, *, validity_days)`; `providers/registry.py::dns_provider_for(zone)` becomes the only DNS construction path (`deploys/` keeps receiving the provider in `desired`, never importing it). `realtime/authorize.py` appends `map.`, `findings`, `host.`, and `site.{id}.traffic` to the topic table. `monitor/collect_once.py` gains the byte-cap degrade summary. `deploys/steps.py::ensure_route_tls` gains the cert-material substep and its named unproxied refusal. Beat: `probe-uptime` (60 s), `cert-expiry-daily`, `cf-token-scope-daily`, `drill-pager-monthly`, `retention-janitor-nightly`, and `due_at` seeding for every drill kind. `check.py --phase 3` is the phase gate; `make conformance` moves to phase 3 minus tiers t2/t3, `conformance-3` is all-tiers and replaces `conformance-2.5` in `nightly-gates`.

## 5. DECISION markers opened

- **D-032** Phase 3 ships DNS/TLS + alerting/monitoring + map/operator-UX + adopt. App-log viewer (§E3), scheduled-jobs UI (§E8/§N7), first-run checklist (§F3) and the backup/restore surface (§E5) move to **Phase 3b**; no registry id moves because none exist for them, and the Scribe amends the §I Phase-3 line at exit.
- **D-033** `DnsZone` is the single DNS-zone identity; `providers/registry.py::dns_provider_for(zone)` is the only construction path. The `HUB_TEST_ZONE_SLUGS`-vs-`HUB_TEST_DNS_ZONE` dual namespace is retired behind it.
- **D-034** One Cloudflare client. `providers/cloudflare.py` is the product adapter **and** the client the credentialed T3 leg drives, under `HUB_TEST_MODE`, against an allowlisted `purpose=test` zone; outside test mode it refuses any `purpose=test` zone. This is D-028's stated reversal condition. `providers/test_dns.py` is retired only after the live leg is green (may-slip).
- **D-035** Proxied sites get Cloudflare Origin certificates issued and pushed by the Hub. Unproxied public sites get a **named refusal**, not Caddy DNS-01 — Hub-central DNS-01 is Phase 3b. SEC-B2 is proven by the refusal plus a no-token-on-target assertion over the pushed artifacts.
- **D-036** The pager is a provider seam (`Pager`/`providers/ntfy.py`/`FakePager`), not a Transport effect: it is a Hub→internet call. Tokens and topic names are vault secrets; bodies are scrubbed and minimized; break-glass text ships only in the email copy, marked advisory-only.
- **D-037** One alert rules table (`monitor/alert_rules.py`) transcribed from alert-protocol §2; `classify()` raises `UnclassifiedAlert` on an unknown kind. That raise is ALERT-P1-ROWS' teeth — a new alert type cannot reach a channel before it has a row.
- **D-038** `Finding` is the persistence for every alert (§F2 + alert-protocol §7); hysteresis/flap/storm counters live on `AlertState` keyed by the same fingerprint so the Finding model stays §F2-shaped.
- **D-039** MON-DEADMAN-EXTERNAL and PROV-J7-COMPOSE-AWARE-ADOPT convert `verify: checklist` → `verify: test`. Neither has an honest gate to name and R4-9 forbids inventing one; both are testable behaviours.
- **D-040** UX-F5's hardware-touch clause is unbuildable before WebAuthn: Phase 3 proves T2 confirm, T3 one-click-with-undo, and "T3 is never behind step-up", files a named waiver for the T1 clause, and Task 0 registers `SEC-F5-T1-HARDWARE-TOUCH` at phase 4 so the split cannot silently collapse.
- **D-041** Map v1 is plain SVG + a list-view toggle. The §J3 library choice (React Flow vs Cytoscape) stays open until a 30-node prototype needs it — zero dependency now, cheap to reverse.
- **D-042** REL-P2's 24 h waiver **stays**. Phase 3 replaces the hub-down stub with a real external prober at the §G monthly 30-min form, writes `due_at` rows so `find_missed` stops being inert in prod, and records the 24 h run as a dated calendar item outside the phase gate.
- **D-043** Credential-gated Cloudflare/LE work keeps the D-031 shape: absent token → `skipped-only` + dated waiver, never a T1-sibling green; and the LE waiver gains the self-refusing probe the 2.5 panel asked for (M4).
- **D-044** Protective cut — §6.
