## 1. What lands this phase

Phase 2.5 left a live substrate: T1/T2/T3 all green on this host (16 T3 passed), CheckRun + drills + reaper, `HUB_TEST_MODE`, `assert_test_zone`, a working `DnsProvider` seam with a real Cloudflare client for **one test zone**. Phase 3 turns that into the operator-facing half of the product.

1. **Product Cloudflare DNS adapter, fail-closed before first use (panel r2).** `providers/cloudflare.py` implements the pinned `DnsProvider` (§D5) against a **`DnsZone`** row that points at a **`DnsAccount`** carrying the three credential refs the product actually needs — `dns_token_ref`, `edge_token_ref`, `origin_ca_key_ref` — each a vault owner id, never a value. `providers/registry.py::dns_provider_for(zone)` is the only construction path and **enforces scope synchronously, before the client is usable**: Bearer only (an `X-Auth-Key`/`X-Auth-Email` Global-API-Key shape is refused outright), `GET /client/v4/user/tokens/verify` must return `success: true` and `result.status == "active"`, and the zone-authorization probe `GET /client/v4/zones?per_page=50` must return **exactly** the one zone whose `id` equals `DnsZone.provider_zone_id` — more zones means excess access and the client refuses to exist (D-046 records why `verify` alone cannot do this). Wrong purpose refuses in both directions. Task 2's daily audit stays, demoted to defense-in-depth: a finding is not enforcement.
2. **SEC-B5 token discipline, mechanised.** The `dns` ref is the only credential the adapter loads; the `edge` ref now has a model home (`DnsAccount`) so the audit is auditing something real rather than an aspiration, and the §6.5 L5 playbook that will use it stays Phase 4. The daily audit compares the probed zone set and token status against the declared minimum and files a P2 Finding on drift.
3. **Origin certificates, `TlsCertificate`, and a refusal the operator can see (panel r2).** `Site` gains `proxied` (default true) and `dns_zone` (FK; nullable **only** for `mesh_only`, enforced by a check constraint). Proxied sites: the Hub generates the keypair, issues a Cloudflare **Origin CA** certificate, stores the key in the vault *before anything is pushed*, writes cert+key atomically through a `0700` root-owned `/srv/sites/{slug}/tls/` (temp name + `mv`, `0400 root:root`), verifies key/cert match and the checksum after write (§B6), then reloads Caddy; a failed reload rolls back to the previous pair and the superseded material is destroyed only after the new pair serves. Unproxied public sites: Hub-central DNS-01 is **not built this phase**; the pipeline refuses, and that refusal surfaces as a **Finding plus a visible Sites-screen state**, never a bare exception. SEC-B2 splits into its two clauses (D-035): the exfiltration clause is proven here by a scan of **every target-bound surface** — `put()` payloads, `run()` argv, env files and env snapshots, Celery task kwargs, `DeploymentArtifact` bodies, generated Caddy/Dockerfile text and the recorded Transport call log — and the DNS-01 clause is registered at phase 4 with a clause-scoped waiver on the full-text id.
4. **Findings model (§F2) as the one attention queue.** `Finding(source_engine, severity, entity, title, body, fix_action, state, first_seen, last_seen, fingerprint)`; accept-risk requires a one-line reason and re-surfaces on fingerprint change. Every alert is a Finding with the same fingerprint (alert-protocol §7); the pager is only the interrupt. `findings` becomes the canonical realtime topic and the Phase-0 `alerts` topic is kept one phase as a deprecated alias (D-045).
5. **Alert protocol, hard-coded.** One rules table transcribed from alert-protocol §2 in `monitor/alert_rules.py`; `classify(kind)` **raises** on an unregistered alert kind (ALERT-P1-ROWS). Anti-noise engine (§4): open after 3 failures / close after 2, flap collapse (≥3 cycles/30 min → one P2 FLAPPING), root-cause suppression (host-down suppresses its sites, zone-down its hosts, suppressed list inside the one alert), ack ≠ resolve, storm breaker (>10 pushes/10 min → one P1 + 10-min summaries), and the mandatory recovery notice.
6. **Delivery has named owners, not implied behaviour (panel r2).** Every §1-table behaviour gets a module and a Beat entry: hourly re-push of unacked P1s and the 24 h `[UNACKED]` email — `monitor/alerts.py::repeat_unacked()` on Beat `alert-repeat-unacked` (300 s scan, not a probe-cycle piggyback, so a stalled probe cycle cannot silence a repeat); P2 grouping (>1 P2 in 10 min = one grouped push) — `monitor/antinoise.py::group_p2()`; the 08:00 P3 digest and the weekly trend rollup — `monitor/digest.py` on Beat `digest-daily` / `digest-weekly`. Email uses Django's mail backend (locmem in tests, env-configured SMTP in prod, `HUB_SMTP_*`); a failed email writes a Finding and never blocks the push path.
7. **ntfy pager as a provider seam, with distinct identities (panel r2).** `Pager` in `providers/base.py`, `providers/ntfy.py`, `FakePager` in `providers/fakes.py` and the default everywhere in tests. Three publisher identity classes, never one shared secret: the **Hub** publisher, the **healthchecks** publisher, and a **per-target** publisher issued at provisioning; read/subscribe access is a separate protected-topic credential that no publisher token can use. Removing `server-watch.sh` from a target revokes that target's publish token (ntfy account API where configured; otherwise the token ref is marked revoked in the vault so the Hub refuses to reissue it, and a P2 Finding carries the one manual step). Push bodies are minimized (object · severity · duration · deep link; host aliases, never raw IPs) and pass the scrubber; break-glass text lives only in the **email** copy, labelled advisory-only.
8. **Watcher-of-the-watcher (§5).** The dead-man ping fires only after a probe cycle completes **every** target; a failed dead-man POST files its own Finding (panel r2) — a watcher that cannot be reached is exactly the silence the switch exists to break — and the receiver's registration is a dated artifact in the phase-3 demo record. The canary rule precedes any mass-outage declaration and degrades to one "Hub egress degraded" P2. `UptimeEvent` rows carry the transitions the hysteresis engine reads; `mesh_only` sites are probed **Hub→tailnet over HTTP through the existing seams** — never a second per-minute SSH session, which §C3 exists to prevent. ws-class sites' primary metric is last-tick age + connection count (§O3).
9. **Log backpressure + traffic ingest (§C4).** Caddy's native roller (`roll_size 100MiB`, `roll_keep 5`) as a versioned catalog entry (D8 bump; logrotate stays as the backstop); the per-pull byte cap gains the degrade path — over the cap the on-host one-liner returns counts by status and top IPs, ingested as a summary flagged `sampled: true`. Minute `TrafficStat` rows land; hour/day rollups and the retention janitor are the cut line.
10. **Operator UX (§F1/§F2/§F4/§F5/§F6/§F8).** Object-centric nav (Home = map + fleet cards, Sites, Targets, Deploys, Findings, Settings); advisors are tabs. Degraded 10 s REST polling with a visible pill when WS is down (RT-35). Action tiers as one declarative table shared server↔client: T2 confirm shows the diff, T3 (rollback/restart/re-run) is one click + undo and can never be gated by step-up; UX-F5 takes the SCAN-M4 clause shape — no full-text marker while the T1 **hardware** clause is unbuilt (D-040). Settings gains the **minimal Cloudflare-connect surface** (panel r2): paste token → verify through the pinned probe → create the `DnsAccount`/`DnsZone` rows; the §F3 first-run checklist that owns the home screen stays Phase 3b. §F6 phone widths are scoped to exactly three screens — finding detail, site status with its T3 actions, deployment status; the map is explicitly desktop-only. Every new state ships in the simulation seed — that is what retires the UX-F8 waiver.
11. **Map v1 (§9.6.1).** Zones → hosts → containers + Hub + Cloudflare edge from one `map.graph` snapshot/topic; solid public vs dashed mesh edges; status never colour-only; list-view toggle. Map "zone" nodes are **`NetworkZone`** — the network the targets sit in — never the new `DnsZone`, which is a DNS-provider object with no place on a topology graph. Plain SVG; the §J3 library question stays open (D-041). Map v1 stays MUST but is the named **first slip candidate** (D-044).
12. **Adopt-existing-site moves to the may-slip line (panel r2, D-044).** The compose-aware work is real but under-specified, and the panel ruled it out of the MUST demo rather than let five open questions be answered mid-implementation. The holes, recorded so 3b starts from a spec and not a memory: **(a)** is a compose stack one Site (V5 compression: one service container + optional static + jobs) or does adoption need a multi-container Site the data model does not have? **(b)** where does the compose file come from — the git URL the Hub already clones (§A4), an operator paste, or a read off the live host? **(c)** temp-subdomain naming and which zone it lives in (the site's own `DnsZone` vs a dedicated adoption zone), plus who cleans it up when a flip is abandoned; **(d)** the DB/volume pointer — an adopted stack's data lives in volumes and a DB the Hub did not create, so "flip DNS" must state whether the data moves, is shared, or is pointed at in place (§N6 blocks a silent strand); **(e)** the site-owned-Caddy-vs-host-Caddy call needs a recorded decision per adopted site, not a per-run prompt. Phase 3 still ships the read-only half if time allows; PROV-J7 and PROV-E6-ADOPT-TEMP-SUBDOMAIN then need a waiver or a phase bump at exit (the D-020 precedent).
13. **Phase 2.5 parked findings retired here:** I5 + M2 (the hub-down drill never had a prober; nothing wrote `due_at`, so `find_missed` was inert in prod) · M1 (restore stub wrote SUCCEEDED) · M4 (LE waiver not self-refusing) · I1 (self-declared `t3` marks were ungated — the gate now requires the skipif to derive from `multipass_available()`) · the dual zone-allowlist namespace · one-way custody parity · the scrubber's single-class token slice (the pager reuses the scrubber, so it becomes load-bearing). **I2** (worker_entry reaching into `tests/`), **I4** (duplicated Multipass driver) and the `_ws_frame` extended-length read loops (`deploys/steps.py:482/487`, moved off Task 3 per the panel) sit on the may-slip line in Task 18.

## 2. Interfaces / tables that change

**One schema wave (panel r2).** Every model change lands in **Task 1** as a single migration; no later task adds a migration unless implementation discovers one, and then in the stated rebase order T1 → T3 → T4 → T6 → T8 → T10.

**New models (all §4-named, none invented):** `DnsAccount(provider, label, dns_token_ref, edge_token_ref, origin_ca_key_ref)` · `DnsZone(account FK, name, provider_zone_id, purpose ∈ {prod, test}, proxied_default)` — **unique on `(provider, name)`** via the account's provider, and `proxied_default` is documented as a **Cloudflare capability** surfaced through `capabilities()`, not a provider-neutral field · `TlsCertificate(site, mode ∈ {origin_cert, uploaded, auto, hub_dns01}, not_after, fingerprint, key_ref, pushed_at)` · `Finding` (§F2 verbatim, `fingerprint` unique, `accepted_reason`) · `AlertState(fingerprint 1:1, consecutive_fail, consecutive_ok, opened_at, closed_at, last_push_at, acked_at, transitions JSON)` · `AlertDelivery(finding, channel ∈ {ntfy, email}, severity, backend, sent_at, ok, detail)` · `UptimeEvent(entity, kind, state, at)` · `TrafficStat(site, bucket_start, granularity, requests, bytes, status_counts JSON, sampled bool)`. **`Site` gains `dns_zone` FK** (nullable only when `exposure == mesh_only`, check-constrained) **and `proxied` (default true)**. `DnsRecord` gains `zone` FK + `observed_value` / `last_verified` (§D3). `CheckRun.Kind` gains `pager`, `cf_token_scope`, `cert_expiry`.

**Interfaces:** `providers/base.py` gains `Pager.publish(...)` and `OriginCertIssuer.issue(zone, hostnames, *, validity_days)`; `providers/registry.py::dns_provider_for(zone)` is the only DNS construction path and performs the fail-closed scope enforcement. **The pipeline now carries a `DnsZone`** — `desired["dns_zone"]` resolved from `Site.dns_zone`, not `Site.primary_target.zone`, which is a `NetworkZone` from which no DNS client is constructible (panel r2 Product Critical); `ensure_dns` takes it and `deploys/` still never imports a provider. `realtime/authorize.py` appends `findings` (canonical), `map.`, `host.`, `site.{id}.traffic`, and keeps `alerts` as a deprecated alias for one phase. `monitor/collect_once.py` gains the byte-cap degrade summary. `deploys/steps.py::ensure_route_tls` gains the cert-material substep and the named unproxied refusal. Beat gains `probe-uptime` (60 s), `alert-repeat-unacked` (300 s), `digest-daily` (08:00 local), `digest-weekly`, `cert-expiry-daily`, `cf-token-scope-daily`, `drill-pager-monthly`, `retention-janitor-nightly`, plus `due_at` seeding for every drill kind. `check.py --phase 3` is the phase gate; `make conformance` moves to phase 3 minus tiers t2/t3, `conformance-3` is all-tiers and replaces `conformance-2.5` in `nightly-gates`.

**Pinned env names (panel r2 minor).** `HUB_TEST_ZONE_SLUGS` survives as the single allowlist and now names `DnsZone.name` values as well as `NetworkZone.slug`s; `HUB_TEST_DNS_ZONE` is **retired** in favour of the `purpose=test` `DnsZone` row; `HUB_TEST_CF_TOKEN` survives as the test-plane token env. Tasks 1 and 17 use exactly these names. Test-plane client construction stays **triple-keyed**: `HUB_TEST_MODE` **and** `purpose == test` **and** the zone name on `HUB_TEST_ZONE_SLUGS`.

## 5. DECISION markers opened

- **D-032** Phase 3 ships DNS/TLS + alerting/monitoring + map/operator-UX. App-log viewer (§E3), scheduled-jobs UI (§E8/§N7), first-run checklist (§F3), the backup/restore surface (§E5) and — per the panel — **adopt-existing-site** move to **Phase 3b**; the Scribe amends the §I Phase-3 line at exit.
- **D-033** `DnsZone` (under a `DnsAccount`) is the single DNS-zone identity, unique on `(provider, name)`; `providers/registry.py::dns_provider_for(zone)` is the only construction path. The `HUB_TEST_ZONE_SLUGS` / `HUB_TEST_DNS_ZONE` dual namespace is retired behind it; `HUB_TEST_ZONE_SLUGS` survives.
- **D-034 (amended, panel ruling 1, 2-1)** One Cloudflare client: `providers/cloudflare.py` is the product adapter **and** the client the credentialed T3 leg drives, under `HUB_TEST_MODE`, against an allowlisted `purpose=test` zone — D-028's stated reversal condition. The single-client concession is bought with mandatory hardening: three separate credential refs on `DnsAccount` (dns / edge / Origin-CA); **synchronous fail-closed scope enforcement at construction** — Bearer only, active token, and an exact one-zone authorization probe — so no code path holds an over-scoped client; the daily audit is defense-in-depth, not the enforcement; and test-zone construction stays triple-keyed (`HUB_TEST_MODE` + `purpose=test` + allowlist).
- **D-035 (amended, panel ruling 2, 3-0)** Proxied sites get Cloudflare Origin certificates issued and pushed by the Hub; unproxied public sites get a **named refusal surfaced as a Finding and a Sites-screen state**, not Caddy DNS-01. SEC-B2's two clauses split: `SEC-B2-NO-TOKEN-ON-TARGET` is proven this phase by a scan of every target-bound surface (put payloads, run argv, env files and snapshots, Celery kwargs, DeploymentArtifacts, generated config text, recorded Transport calls); `TLS-B2-HUB-DNS01-UNPROXIED` is registered at phase 4; the full-text id carries **no marker** and a clause-scoped waiver until both clauses hold.
- **D-036** The pager is a provider seam (`Pager`/`providers/ntfy.py`/`FakePager`), not a Transport effect. Distinct Hub / healthchecks / per-target publisher identities; subscriber read access is its own protected credential; decommissioning a target revokes its publish token. Bodies scrubbed and minimized; break-glass only in the email copy, advisory-only.
- **D-037** One alert rules table (`monitor/alert_rules.py`) transcribed from alert-protocol §2; `classify()` raises `UnclassifiedAlert` on an unknown kind. Every §1 delivery behaviour (unacked repeat, P2 grouping, digest, weekly rollup) has a named module and Beat entry, so no row of the protocol is owned by nobody.
- **D-038** `Finding` is the persistence for every alert (§F2 + alert-protocol §7); hysteresis/flap/storm counters live on `AlertState` keyed by the same fingerprint so the Finding model stays §F2-shaped.
- **D-039 (panel ruling 3, 2-1)** MON-DEADMAN-EXTERNAL and PROV-J7-COMPOSE-AWARE-ADOPT convert `verify: checklist` → `verify: test`; neither has an honest gate to name and R4-9 forbids inventing one. Conditions: a failed dead-man POST files its own Finding, and the external receiver's registration is a dated artifact in the phase-3 demo record.
- **D-040 (amended, panel ruling 4, 3-0)** `SEC-F5-T1-HARDWARE-TOUCH` is registered at **phase 4** in Task 0; `UX-F5-T2-T3-FRICTION` carries the clauses Phase 3 can prove; the full-text `UX-F5-ACTION-TIERS` carries **no marker** and a clause-scoped waiver while the hardware clause is unbuilt — the SCAN-M4 shape, so the split cannot silently collapse.
- **D-041** Map v1 is plain SVG + a list-view toggle; map "zone" nodes are `NetworkZone`. The §J3 library choice stays open until a 30-node prototype needs it.
- **D-042** REL-P2's 24 h waiver **stays**. The hub-down drill gets a real external prober at the §G 30-min form, `due_at` rows so `find_missed` works in prod, and a defined no-eligible-site outcome (`SKIPPED` + reason + P2 Finding) so nightly stays honest and green on a siteless host.
- **D-043** Credential-gated Cloudflare/LE work keeps the D-031 shape: absent token → `skipped-only` + dated waiver, never a T1-sibling green; the LE waiver gains the self-refusing probe (2.5 finding M4).
- **D-044 (amended, panel ruling 5)** Protective cut — §6. Task 15 (adopt) leaves the MUST line for Phase 3b; Task 14 (map v1) stays MUST and is the **named first slip candidate** if the phase runs long.
- **D-045 (new, r2)** One attention stream: `findings` is the canonical realtime topic; the Phase-0 `alerts` topic remains authorized as a **deprecated alias** for one phase (same payload, asserted by test) and the simulation seed moves to `findings`. Retiring it outright in this phase would break P0-AUTHZ-TOPIC and the seed for no operator benefit.
- **D-046 (new, r2)** Cloudflare zone authorization is established by the **zone-set probe**, not by `/user/tokens/verify`: verify returns `{result.id, result.status}` and no scope list, so it can only prove the credential is a live token. `GET /zones?per_page=50` returning exactly the expected `provider_zone_id` is what proves the token is not over-scoped, and a Global API Key is refused by header shape before either call. Reversal: a Cloudflare API that returns a token's policy set to the token itself.
